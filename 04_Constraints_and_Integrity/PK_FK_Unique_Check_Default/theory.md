# PK, FK, Unique, Check, Default Constraints & Identity Management

## Overview
Database constraints enforce data integrity rules directly at the engine level. They prevent bad or inconsistent data from entering the database, ensuring domain, entity, and referential integrity.

---

## 1. Primary Key (PK) & Identity Management

A Primary Key uniquely identifies each row in a table. It implicitly enforces **`UNIQUE`** and **`NOT NULL`**.

### SQL Server (T-SQL) Syntax
```sql
CREATE TABLE dbo.Student (
    -- Auto-increments starting at 1, step by 1
    StudentID INT IDENTITY(1,1) PRIMARY KEY,
    StudentName VARCHAR(100) NOT NULL
);
```

### PostgreSQL Syntax
```sql
-- ANSI Standard Identity (PostgreSQL 10+)
CREATE TABLE Student (
    StudentID INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    StudentName VARCHAR(100) NOT NULL
);

-- Legacy PostgreSQL Auto-Increment
-- StudentID SERIAL PRIMARY KEY
```
> ℹ️ **PostgreSQL Note**: SQL Server uses `IDENTITY(1,1)`. Modern PostgreSQL uses standard ANSI `GENERATED ALWAYS AS IDENTITY` (or `GENERATED BY DEFAULT AS IDENTITY`).

## 2. Managing Auto-Increment Identifiers

### A. Inserting Explicit Key Values

#### SQL Server (T-SQL)
```sql
-- Enable manual identity insertion
SET IDENTITY_INSERT dbo.Student ON;

INSERT INTO dbo.Student (StudentID, StudentName)
VALUES (999, 'Migrated Student');

-- Always disable after completion
SET IDENTITY_INSERT dbo.Student OFF;
```

#### PostgreSQL
```sql
-- For GENERATED ALWAYS AS IDENTITY columns, use OVERRIDING SYSTEM VALUE:
INSERT INTO Student (StudentID, StudentName)
OVERRIDING SYSTEM VALUE
VALUES (999, 'Migrated Student');

-- For GENERATED BY DEFAULT AS IDENTITY or SERIAL, insert directly without special flags.
```

### B. Checking & Reseeding Identity Counters

#### SQL Server (T-SQL)
```sql
-- Inspect current identity value
DBCC CHECKIDENT ('dbo.Student', NORESEED);

-- Reseed identity counter to start next row at 501
DBCC CHECKIDENT ('dbo.Student', RESEED, 500);
```

#### PostgreSQL
```sql
-- Check current sequence value
SELECT last_value FROM student_studentid_seq;

-- Reseed identity sequence counter to start next row at 501
SELECT setval(pg_get_serial_sequence('student', 'studentid'), 500);
```

### C. Identity Retrieval Functions Reference (T-SQL)

| Function | Scope & Session | Usage & Best Practice |
| :--- | :--- | :--- |
| **`SCOPE_IDENTITY()`** | Current Scope / Current Session | **Recommended**. Returns last identity created in current procedure/scope. Safe from trigger interference. |
| **`@@IDENTITY`** | Any Scope / Current Session | Returns last identity generated anywhere in current session (can be overwritten by triggers). |
| **`IDENT_CURRENT('tbl')`** | Any Scope / Any Session | Returns last identity for a specific table across ALL active user connections. |

> ℹ️ **PostgreSQL Equivalent**: Use `RETURNING StudentID` at the end of the `INSERT` query (e.g., `INSERT INTO Student (StudentName) VALUES ('Alice') RETURNING StudentID;`).

## 3. Foreign Key (FK) Constraint

Enforces referential integrity by validating that values in a child column exist in the referenced parent table.

### T-SQL (SQL Server) & PostgreSQL Syntax (Identical)
```sql
CREATE TABLE Department (
    DepartmentID INT PRIMARY KEY,
    DepartmentName VARCHAR(50) NOT NULL
);

CREATE TABLE Student (
    StudentID INT PRIMARY KEY,
    StudentName VARCHAR(100) NOT NULL,
    DepartmentID INT,
    CONSTRAINT FK_Student_Department
        FOREIGN KEY (DepartmentID)
        REFERENCES Department(DepartmentID)
);
```

### Execution Walkthrough: Violation Test

**Initial State:** `Department` has `DepartmentID = 1` ('Science') and `DepartmentID = 2` ('Arts').

```sql
-- Attempting to insert a student into a non-existent department (99):
INSERT INTO Student (StudentID, StudentName, DepartmentID)
VALUES (101, 'Eve', 99);
```

#### Expected Output:
* **SQL Server**: `Msg 547, Level 16: The INSERT statement conflicted with the FOREIGN KEY constraint "FK_Student_Department".`
* **PostgreSQL**: `ERROR: insert or update on table "student" violates foreign key constraint "fk_student_department"`.
* **Result**: Row insertion is **rejected**.

## 4. Unique Constraint

Ensures all non-null values in a column or set of columns are distinct.

### T-SQL & PostgreSQL Syntax
```sql
CREATE TABLE Employee (
    EmployeeID INT PRIMARY KEY,
    Email VARCHAR(100) CONSTRAINT UQ_Employee_Email UNIQUE
);
```

### Critical Behavior Difference: Handling `NULL` Values

```sql
INSERT INTO Employee (EmployeeID, Email) VALUES (1, NULL);
INSERT INTO Employee (EmployeeID, Email) VALUES (2, NULL); -- Second NULL insertion
```

#### Behavior Comparison:
* **SQL Server**: **Fails on 2nd insert!** SQL Server considers `NULL = NULL` for unique constraints (only 1 `NULL` allowed per unique index).
  * *SQL Server Fix*: Create a filtered unique index: `CREATE UNIQUE INDEX UX_Emp_Email ON Employee(Email) WHERE Email IS NOT NULL;`
* **PostgreSQL**: **Succeeds!** By standard default, PostgreSQL treats `NULL` values as distinct, allowing multiple `NULL` entries. (PostgreSQL 15+ supports `UNIQUE NULLS NOT DISTINCT` if you want SQL Server's behavior).

## 5. Check Constraint

Enforces a logical boolean predicate on column values during `INSERT` or `UPDATE`.

### T-SQL & PostgreSQL Syntax
```sql
CREATE TABLE Product (
    ProductID INT PRIMARY KEY,
    Price DECIMAL(10,2) CONSTRAINT CK_Product_Price CHECK (Price > 0),
    Stock INT CONSTRAINT CK_Product_Stock CHECK (Stock >= 0)
);
```

### Execution Walkthrough: Violation Test

```sql
INSERT INTO Product (ProductID, Price, Stock)
VALUES (1, -15.50, 10);
```

#### Expected Output:
* **SQL Server**: `Msg 547, Level 16: The INSERT statement conflicted with the CHECK constraint "CK_Product_Price".`
* **PostgreSQL**: `ERROR: new row for relation "product" violates check constraint "ck_product_price"`.
* **Result**: Transaction is aborted.

---

## 6. Default Constraint

Supplies a fallback default value whenever an `INSERT` statement omits the target column.

### T-SQL (SQL Server) Syntax
```sql
CREATE TABLE Customer (
    CustomerID INT PRIMARY KEY,
    City VARCHAR(100) CONSTRAINT DF_Customer_City DEFAULT 'Cairo',
    CreatedDate DATETIME CONSTRAINT DF_Customer_CreatedDate DEFAULT GETDATE()
);
```

### PostgreSQL Syntax
```sql
CREATE TABLE Customer (
    CustomerID INT PRIMARY KEY,
    City VARCHAR(100) DEFAULT 'Cairo',
    CreatedDate TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
> ℹ️ **PostgreSQL Note**: In PostgreSQL, `CURRENT_TIMESTAMP` or `NOW()` is used instead of SQL Server's `GETDATE()`.

### Execution Walkthrough

```sql
INSERT INTO Customer (CustomerID) VALUES (1);
```

#### Resulting Row:
| CustomerID | City | CreatedDate |
| :--- | :--- | :--- |
| **1** | `Cairo` | `2026-09-08 14:15:00` |

---

## 7. Summary & Decision Matrix

| Constraint | SQL Server (T-SQL) | PostgreSQL | Primary Purpose |
| :--- | :--- | :--- | :--- |
| **Primary Key** | `IDENTITY(1,1)` | `GENERATED ALWAYS AS IDENTITY` | Entity uniqueness & row identification |
| **Foreign Key** | `REFERENCES Parent(Col)` | `REFERENCES Parent(Col)` | Referential integrity & relationship validity |
| **Unique** | Allows **1 `NULL`** | Allows **multiple `NULL`s** | Prevents duplicate field values |
| **Check** | `CHECK (Condition)` | `CHECK (Condition)` | Domain validation & business rules |
| **Default** | `DEFAULT GETDATE()` | `DEFAULT CURRENT_TIMESTAMP` | Fallback values for omitted columns |
