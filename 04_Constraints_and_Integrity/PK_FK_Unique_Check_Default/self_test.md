# Self-Test — PK, FK, Unique, Check, Default Constraints

**Q1. What does a primary key do?**

<details>
<summary>Show answer</summary>
It uniquely identifies each row in a table.
</details>

**Q2. What is a foreign key?**

<details>
<summary>Show answer</summary>
A foreign key references the primary key of another table to enforce a relationship.
</details>

**Q3. What is the purpose of a UNIQUE constraint?**

<details>
<summary>Show answer</summary>
It prevents duplicate values in a specified column or set of columns.
</details>

**Q4. What does a CHECK constraint enforce?**

<details>
<summary>Show answer</summary>
It enforces a business rule or valid value range.
</details>

**Q5. What is a DEFAULT constraint?**

<details>
<summary>Show answer</summary>
It assigns a value when the column is not explicitly supplied.
</details>

**Q6. Why are constraints important?**

<details>
<summary>Show answer</summary>
They protect data integrity, reduce invalid values, and maintain consistent relationships.
</details>

---

## Quick revision

- PK = unique row identifier
- FK = referenced relationship between tables
- UNIQUE = no duplicate values
- CHECK = validity rule
- DEFAULT = fallback value
